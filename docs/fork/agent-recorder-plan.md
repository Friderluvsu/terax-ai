# План: регистратор ИИ-агентов

Статус: план, не реализовано. Исследование открытых проектов выполнено 2026-11-02.

## Цель

Terax уже знает, когда в терминале работает агент (Claude Code, Codex, Gemini, Pi, OpenCode, Grok), и видит его состояния через OSC 133 и хуки. Регистратор добавляет память: что агент делал в каждой сессии, какие файлы менял, сколько это стоило, и даёт быстро найти прошлую работу.

Требования продукта: ноль ресурсов, пока функция выключена или агентов нет; всё локально; секреты маскируются до индексации; никакого отдельного демона.

## Главное решение: читать журналы агентов, а не записывать терминал

Все сильные проекты (agentsview, ccusage, claude-code-log) читают собственные журналы агентов. Сырой вывод PTY для TUI-агентов огромен, перерисовывается постоянно и почти не поддаётся поиску. Поэтому:

| Источник | Роль |
| --- | --- |
| Журналы агентов (JSONL, SQLite) | основной источник смысла: промпты, вызовы инструментов, ответы, токены |
| Хуки Terax (`agent_enable_hooks`) | живая связь вкладки с `session_id` и `transcript_path` |
| Жизненный цикл OSC 133 | границы сессии, привязка к блокам терминала |
| Git HEAD до и после хода | связь сессии с изменениями и коммитами |
| asciicast v3 | необязательный визуальный повтор, по умолчанию выключен |

## Где лежат данные

| Агент | Расположение | Надёжность |
| --- | --- | --- |
| Claude Code | `~/.claude/projects/<cwd>/<sessionId>.jsonl`, чекпоинты в `~/.claude/file-history/<sessionId>/`, хук получает `transcript_path` | подтверждено; Claude удаляет журналы старше 30 дней |
| Codex | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` (`$CODEX_HOME`), строки `session_meta`, `turn_context`, `response_item`, `event_msg` | сторонние описания |
| Gemini CLI | `~/.gemini/tmp/<project>/chats/session-*.jsonl` (старые версии: `.json`) | не подтверждено |
| OpenCode | `~/.local/share/opencode/opencode.db` (SQLite, открывать только на чтение) плюс старый `storage/` | сторонние описания |
| Pi | `~/.pi/agent/sessions/` | не подтверждено |
| Grok | `~/.grok/sessions/` | не подтверждено |

Форматы меняются между версиями: парсеры должны быть терпимыми, а каждый формат покрыт fixture-тестами.

## Возможности по приоритету

1. Индексация журналов только пока вкладка с агентом жива; привязка вкладки к сессии через `session_id` из хука, запасной вариант: cwd и время старта.
2. Архив Claude-журналов в хранилище Terax (zstd), потому что Claude сам удаляет их через 30 дней.
3. Лента сессии по ходам: промпт, инструменты с диффами и кодами выхода, ответ. Блоки инструментов сворачиваются.
4. Поиск по всем агентам: SQLite FTS5, фильтры по агенту, проекту, дате, инструменту. Индекс строится лениво при первом открытии.
5. Изменения по ходам: HEAD в начале и конце хода, список файлов; опционально trailer в коммите (как Entire) или git notes (как git-ai).
6. Стоимость и токены по сессии, ходу и модели; правила дедупликации из ccusage, офлайн-таблица цен.
7. Маскировка секретов при загрузке (правила в духе gitleaks плюс deny-list Terax); сырые секреты не попадают в индекс.
8. Переход от блока терминала к ходу в ленте и обратно через существующие пины блоков.
9. Аналитика сбоев: упавшие инструменты, отказы в разрешении, прерывания, повторы.
10. Экспорт одной сессии в HTML или Markdown с маскировкой.
11. Повтор в формате asciicast v3 с маркерами жизненного цикла: опционально, с лимитом размера.
12. Инструмент поиска по архиву для встроенного агента Terax и для телефона (`terax-cli`).

## Архитектура

Rust, новый модуль `src-tauri/src/modules/recorder/`:

- `sources/{claude,codex,gemini,opencode}.rs`: чистые парсеры строка→событие, без ввода-вывода, с fixture-тестами.
- `tail.rs`: следит за одним файлом журнала, пока жива связанная вкладка (`notify` уже есть в зависимостях). После завершения сессии файл дочитывается и наблюдатель закрывается.
- `store.rs`: SQLite с FTS5 в `app_data_dir()/recorder/` (новая зависимость `rusqlite` с bundled-сборкой, оценить вклад в размер бинарника до начала работ).
- `redact.rs`: чистая маскировка, общий список правил с `ai/lib/redact`.
- Команды: `recorder_sessions`, `recorder_session`, `recorder_search`, `recorder_export`.

Frontend, модуль `src/modules/recorder/`, весь UI за `lazy()`:

- вкладка нового вида `agent-session` (лента хода);
- панель в сайдбаре: список сессий, поиск, фильтры;
- кнопка «История» в карточке агента у `NotificationBell`.

Настройки в разделе Fork: включить регистратор, архивировать Claude-журналы, хранить N дней, визуальный повтор.
