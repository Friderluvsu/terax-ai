# План: оркестрация агентов

Статус: этап O1 реализован (2026-11-03), O2-O5 не начаты. Решения приняты 2026-11-03.

O1 в коде: `terax orchestrate`, `terax task create|list|stop`, `terax run stop`. Роль вызывающей панели определяется по её личному токену управления, а не по `TERAX_PANE_ID` из запроса. Задача после завершения агента остаётся `running` и держит слот, пока оркестратор не вызовет `terax task stop`; автоматическое определение завершения относится к O2. Флаги полной автономии (`bypassPermissions`, песочница) пока не передаются: они включаются только вместе с ограничениями из O2.

## Зачем

Сейчас Terax запускает от одного до четырёх агентов в панелях, но координирует их человек: раздаёт задачи, следит за статусами, проверяет, сливает ветки, решает конфликты. Оркестрация переносит эту работу на одного агента-оркестратора, а Terax даёт ему безопасные инструменты и показывает человеку доску с результатами.

## Принятые решения

| Вопрос | Решение |
| --- | --- |
| Кто планирует | Claude Code в обычной вкладке Terax через команду `terax` (свой ИИ-планировщик не пишем) |
| Изоляция | отдельный `git worktree` и ветка `task/<id>` на каждую задачу |
| Автономия | полная: исполнители работают без подтверждений внутри своего worktree |

Полная автономия допустима только вместе с ограничениями ниже. Они не обсуждаются и включены всегда.

## Роли

- **Оркестратор**: панель, которую пользователь явно назначил (`terax orchestrate` или кнопка). Только он может создавать задачи и запускать исполнителей.
- **Исполнитель**: агент в своём worktree. Видит только свою задачу, не может запускать других агентов, не может пушить и сливать.
- **Человек**: ставит цель, смотрит доску (на Mac или телефоне), одобряет слияние в рабочую ветку.

Роль определяется по `TERAX_PANE_ID` вызывающей панели, который Terax уже передаёт в каждую оболочку вместе с адресом и токеном управления. Вызов `task.create` из панели исполнителя отклоняется в Rust, так что рекурсивного размножения агентов нет.

## Как работает

1. Пользователь в вкладке Claude Code пишет цель, например «добавь экспорт сессий и тесты».
2. Claude Code делит её на задачи и для каждой вызывает `terax task create --agent claude --brief brief.md --files "src/modules/recorder/**"`.
3. Terax создаёт worktree от текущей ветки, отдельный `CARGO_TARGET_DIR`, свободный порт для dev-сервера, вкладку в пространстве «Оркестр» и запускает агента с брифом и правилами задачи.
4. Оркестратор ждёт: `terax task wait --any` возвращается, когда задача завершилась, упала или зависла.
5. Когда исполнитель закончил (хук `Stop`), Terax сам запускает проверки задачи в её worktree и сохраняет результат: прошло или упало, diff stat, стоимость из регистратора.
6. Оркестратор читает `terax task diff <id>` и `terax task check <id>`, при необходимости отправляет исполнителю уточнение (`terax task send`) или запускает новую задачу на исправление.
7. Готовые задачи сливаются в интеграционную ветку `orchestra/<run>` в порядке зависимостей. Конфликт превращается в отдельную задачу.
8. Человек видит итог на доске и одобряет слияние `orchestra/<run>` в свою ветку. Это единственный шаг, который всегда за человеком.

## Ограничения при полной автономии

| Риск | Ограничение |
| --- | --- |
| Агент выходит за пределы задачи | рабочая папка только worktree; Claude Code запускается с `--permission-mode bypassPermissions` плюс песочница (`sandbox` в настройках проекта), чтобы запись вне worktree и сеть кроме реестров пакетов были закрыты; для Codex `--sandbox workspace-write` |
| Порча общей истории | исполнителям запрещены `push`, `merge`, `reset --hard` на чужие ветки: git-хук `pre-push` в worktree и deny-правила в настройках агента |
| Секреты | worktree без `.env*`; deny-list Terax применяется к командам `task.*` |
| Бесконечная работа | лимиты на задачу: время (по умолчанию 45 мин), без прогресса 10 мин, бюджет в долларах из регистратора; превышение останавливает агента |
| Нехватка памяти | не больше 4 исполнителей одновременно (каждый 300-500 MB), очередь для остальных |
| Конфликты ресурсов | отдельный `CARGO_TARGET_DIR` и порт на задачу; порт 1420 только у основной копии |
| Аварийная остановка | кнопка «Остановить всё» на доске и на телефоне: завершает всех исполнителей, worktree сохраняются |

## Команды управления

Расширение существующего протокола `terax-control-protocol` (сейчас `ping`, `capabilities`, `identify`, `open`). Все методы проходят через Rust, проверяют роль вызывающей панели и пишут событие в журнал запуска.

| Метод | Кто может | Что делает |
| --- | --- | --- |
| `task.create` | оркестратор | worktree, ветка, вкладка, запуск агента с брифом |
| `task.list` | оркестратор, человек | задачи и статусы |
| `task.wait` | оркестратор | ждёт смены статуса одной или любой задачи, с таймаутом |
| `task.screen` | оркестратор | последние строки экрана исполнителя |
| `task.send` | оркестратор | текст исполнителю |
| `task.diff`, `task.check` | оркестратор | diff и результат проверок |
| `task.merge` | оркестратор | слияние в `orchestra/<run>` |
| `task.stop`, `run.stop` | оркестратор, человек | остановка задачи или всего запуска |

Тот же набор потом отдаётся как MCP-сервер, чтобы Codex и Gemini тоже могли быть оркестраторами.

## Модули

- Rust: `src-tauri/src/modules/orchestra/` (`run.rs` состояние запуска, `worktree.rs` создание и удаление копий, `limits.rs` чистая логика лимитов, `checks.rs` запуск проверок). Состояние запуска хранится в `app_data_dir()/orchestra/<run>.json`, чтобы пережить перезапуск Terax.
- CLI: подкоманды `terax task …` в `src-tauri/crates/terax-cli`.
- Frontend: `src/modules/orchestra/` с доской за `lazy()`; вкладки исполнителей обычные терминальные вкладки в пространстве «Оркестр».
- Телефон: раздел «Оркестр» в веб-клиенте `mobile/page`: доска, ответ исполнителю, «Остановить всё», одобрение слияния.
- Регистратор (см. [план регистратора](agent-recorder-plan.md)) даёт стоимость и журнал каждой задачи; без него лимит бюджета выключен.

## Этапы

| Этап | Результат | Проверка |
| --- | --- | --- |
| O1 | `task.create/list/stop`, worktree, вкладки, роль оркестратора | тест: исполнитель не может вызвать `task.create`; worktree удаляется только явно |
| O2 | `task.wait/screen/send`, лимиты времени и памяти | тесты чистой логики лимитов; ручной запуск двух задач |
| O3 | `task.check/diff/merge`, интеграционная ветка | тест слияния и конфликта на временном репозитории |
| O4 | доска в Terax и на телефоне, «Остановить всё» | ручная проверка с телефона |
| O5 | бюджет через регистратор, MCP-сервер | сверка стоимости с ccusage |

## Открытые вопросы

- Удалять ли worktree после слияния сразу или хранить N дней.
- Нужен ли режим «план на одобрение»: оркестратор показывает список задач, человек подтверждает перед запуском.
- Как назначать модель исполнителям (дешевле для механических задач).
