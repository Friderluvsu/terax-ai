# Устройство Terax и лимиты размера

Проверено 13 октября 2026 года на личном форке, версия в package.json: 0.9.0-beta. Исходная точка сравнения: 7f4fa36. Изменения оптимизации находятся в ветке task/OPT-01.

## Что это за проект

Terax объединяет терминал, редактор кода, файловый проводник, Git, предпросмотр и панель ИИ. В личном форке добавлены SSH-пространства, работа с удалёнными файлами, HTML Code / Split / Preview, улучшения ввода команд и безымянные вкладки редактора с сохранением черновиков.

Приложение состоит из двух частей:

- Rust и Tauri управляют системными процессами, терминалами, файлами, SSH, Git и хранилищем ключей.
- React и TypeScript показывают интерфейс в системном WebView. Редактор построен на CodeMirror 6. Терминал использует Ghostty через WASM, WebGPU и резервный WebGL.

У встроенного ИИ свои API-ключи или локальная модель. Агент, запущенный командой Claude Code или Codex внутри терминала, является отдельной программой со своими условиями доступа.

README на русском отстаёт от кода: упоминания xterm.js уже не соответствуют текущей реализации. При работе с архитектурой основным документом служит TERAX.md.

## Какой лимит найден

Это бюджет сборки, который авторы задают для контроля роста приложения. Проверка `pnpm size` сравнивает размеры файлов с порогами в `.size-limit.mjs`.

| Что измеряется | Порог |
| --- | ---: |
| Все JavaScript-файлы клиента, включая отложенные модули | 1505 KB gzip |
| JavaScript при запуске главного окна, со всеми статическими зависимостями | 540 KB gzip |
| JavaScript при запуске окна настроек | 540 KB gzip |
| Основной модуль терминала и его общие модули | 56 KB gzip |
| Резервный WebGL | 15 KB gzip |
| Обе поставляемые версии WASM терминала | 450 KB gzip |

Здесь KB означает 1000 байт. gzip применяется отдельно к каждому файлу с уровнем 9, результаты суммируются.

Это не лимит операционной системы, не ограничение числа функций и не размер установленного приложения. При превышении падает проверка размера; само приложение не прекращает работу из-за этого порога. Бюджет можно осознанно изменить, если новая возможность оправдывает дополнительный объём.

Перенос в `lazy()` помогает загрузке при запуске. Он не исключает файл из суммарного бюджета: файл остаётся в поставке.

При первичной проверке существующие `.app` в `/Applications` и каталоге релизной сборки занимали примерно 10 MiB по `du`. Это отдельная величина: нативный бинарник, интерфейс, WASM, шрифты и другие ресурсы. Объём RAM также измеряется отдельно; размер gzip не позволяет его определить. Последующая проверка работающего приложения и установка новой сборки записаны в [отчёте о runtime-оптимизации](runtime-optimization-2026-10-13.md).

## Выполненная оптимизация

У старой конфигурации упаковки обнаружена проблема: общие зависимости React попадали в группы библиотек ИИ. В результате главное окно и настройки статически импортировали Anthropic, Cerebras и общий AI SDK, хотя исходные импорты провайдеров были отложены.

Дополнительно старая проверка запуска считала лишь четыре шаблона имён файлов. Она показывала 215,778 KB, пропуская большую часть реального графа загрузки.

Конфигурация Vite теперь сначала выделяет зависимости первоначальной загрузки в группу startup-vendor. Затем собирает группы отдельных функций. Проверка размера обходит готовые HTML-файлы, modulepreload, импорты и реэкспорты JavaScript, учитывает каждый файл один раз и исключает динамические импорты. Общий бюджет сохранён.

| Метрика | До | После |
| --- | ---: | ---: |
| Главный экран: полный статический граф JS | 656,377 KB | 503,565 KB |
| Окно настроек: полный статический граф JS | 411,689 KB | 353,004 KB |
| Весь клиентский JS | 1501,477 KB | 1489,368 KB |
| Запас до общего лимита | 3,523 KB | 15,632 KB |

При запуске главного окна загружается на 23,3% меньше JS по gzip-метрике. Общий объём уменьшился на 12,109 KB. Статических импортов именованных AI SDK-групп у обоих окон больше нет.

Это измерения состава сборки. Время запуска, RAM и интерактивная работа установленного приложения после изменения не измерялись.

## Что оптимизировать дальше

1. Проверить совместимые дубли зависимостей. В исходной сборке присутствуют несколько версий общих AI SDK-пакетов, Radix, Lezer и style-mod. Объединять их следует после проверки совместимости; два разных основных выпуска marked нельзя заменять одним без анализа поведения.
2. Снимать полный граф запуска после добавления крупных функций. Одни только тесты исходных импортов не обнаружили найденную проблему упаковки.
3. Измерять память отдельно на реальных сценариях: много терминалов, большой вывод, открытые редакторы и включённые языковые серверы. Механизмы ограничения очередей и освобождения графических ресурсов уже реализованы; снимать их ради формального уменьшения кода не стоит.

Набор иконок тоже проверен: из 659 иконок используются 619. Удаление остальных даёт лишь около 2,5 KB gzip на данных набора и требует поддерживать дополнительную обработку сборки. Для первого этапа такая оптимизация малоэффективна.
